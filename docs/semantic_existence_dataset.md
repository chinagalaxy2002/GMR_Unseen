# Semantic novelty × target existence: Charades-STA pipeline

## Input and provenance

- `data/raw/charades_sta/charades_pos_{train,test}.jsonl` are copies of the existing GMR `pos_only` Charades-STA export in `/home/guoxiangyu/paper/新建文件夹/MomentofUntruth/dataset/charades-sta/`. Its queries and temporal windows are human positive annotations. The pipeline never invents positive windows.
- `data/raw/charades/annotations/Charades_v1_{train,test}.csv` and `Charades_v1_classes.txt` come from `downloads/Charades.zip`. Video-level action annotations are used as **positive conflict evidence** for proposed negatives.
- VerbNet 3.4 XML is in `external/verbnet/verbnet3.4`. The installed NLTK WordNet corpus supplies sense IDs. spaCy `en_core_web_sm` provides the dependency parse. These IDs are metadata; the primary novelty key is an inflection-normalized predicate (including relevant particles) or predicate-object pair. Word sense disambiguation is not claimed.
- Action Genome annotations are at `data/raw/action_genome/annotations/object_bbox_and_relationship.pkl`, downloaded from the official repository's Google Drive link. Matching sampled-frame relationships reject negative candidates at video level. Missing Action Genome edges are never interpreted as proof of absence.

## Rebuild

```bash
/home/guoxiangyu/miniconda3/envs/owvtg/bin/python scripts/build_semantic_existence.py
/home/guoxiangyu/miniconda3/envs/owvtg/bin/python scripts/validate_semantic_existence.py
/home/guoxiangyu/miniconda3/envs/owvtg/bin/python scripts/review_semantic_existence.py
```

The official Charades-STA test videos stay in test. A deterministic SHA-256 video-ID bucket reserves 10% of the original training videos for validation. Downstream training inventory is built solely from the remaining training videos. Actions `open` and `close` are held out; up to 16 action-object pairs with enough real train and test positives are selected by a deterministic rule. All training queries containing either held-out verb anywhere in the sentence, plus selected held-out pairs, are removed before inventory construction. The full selection is recorded in `semantic_inventory.json`.

The canonical graph contains agent, action, object, relation, location, and temporal relation fields. Unknown fields remain null. Only queries with a parsed action and object enter the current four-quadrant export. `U+` consists of original, annotated positives whose action or selected composition was held out. `S+` consists of original positives whose composition occurs in downstream training. Positives with an unselected, unseen composition are excluded from the primary split.

Counterfactual candidates change one semantic event edge. Verb edits include `open` ↔ `close`, `take off` ↔ `put on`, `take out` ↔ `put in`, `put down` ↔ `pick up`, and guarded `hold` ↔ `throw`, `drink` ↔ `pour`, `dress` ↔ `undress`, `enter` ↔ `leave`. A phrasal predicate may require two surface token edits while remaining one semantic change. Object edits use curated nearby concepts. A target action-object pair must occur in a real positive query somewhere in the corpus. The edited sentence is reparsed and dropped if its graph changes unexpectedly. Candidates are also rejected if the target pair has positive evidence in another query for that video, Charades action metadata, or available Action Genome graphs. This is a conflict filter only. Its surviving rows are **not** verified absent.

Review each proposed negative against the **whole video**. Enter `absent`, `present`, or `ambiguous` in a copy of the CSV, plus reviewer identity and notes. Use `present` when the target occurs anywhere; use `ambiguous` when the video or wording prevents a confident decision. Then run:

```bash
/home/guoxiangyu/miniconda3/envs/owvtg/bin/python scripts/review_semantic_existence.py --reviews path/to/completed_reviews.csv
```

Only `absent` decisions enter `test_reviewed.jsonl`. The reviewed file is the one to use for formal GMR scoring. The unreviewed candidate file must never be treated as ground truth. The review command also filters `matched_u_pairs_reviewed.jsonl` to pairs with a confirmed negative.

## Evaluation and remaining quality controls

Report S+/S−/U+/U− separately. For U+, report false refusal `FRR_U+ = rejected_U+ / total_U+`. For U−, report rejection `RR_U− = rejected_U− / total_U−`. Positive localization scores require the original temporal windows; negative rows use an empty `relevant_windows` list. The candidate audit is descriptive, not an evaluation result.

There is a known surface-form confounder: all positive queries are original human text and all negatives are edited text. The release includes `text_only_diagnostic.json` to quantify residual label signal. Query length differs between seen and unseen subsets because of which real actions were selected; matched-pair evaluation reduces this risk but does not remove it. Action Genome is incomplete even when loaded, so video review remains required; this release records the dataset owner's global review attestation rather than a per-qid review file. The final files and provenance are documented in `data/release/semantic_existence_v1/HANDOFF.md`.
