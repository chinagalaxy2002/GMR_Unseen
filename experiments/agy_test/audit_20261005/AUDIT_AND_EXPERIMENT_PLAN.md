# GMR 未见语义拒绝退化：独立核验与实验建议

日期：2026-10-05。范围：用户指定的 `results_final` 五个划分、原始 QD-DETR-GMR 基线、缓存、训练/评估代码、技术报告与工作记录。新增审计文件位于本目录；原模型、预测、基线发布包与历史报告未改写。未执行新训练。

## 判定

**数值上确实缩小了 Seen–Unseen AUROC Gap；现有证据尚不能证明稳定改善了未见语义的拒绝识别，也不能支持报告所述的池化失效因果确证。**

原因是：Seen AUROC 明显下降，Unseen 增益集中于两组，宏平均 Unseen 增益的区间包含零，固定 Seen 阈值下仍有严重的几乎全接受现象。此外，发布基线和最终结果原先使用不同精度的分数；缓存推理与原基线输入路径存在不一致；文本特征存在与正负来源相关的差异；报告所写机制与最终 checkpoint 的实际结构不一致。

当前最可信的结果是下述“原 checkpoint 全量测试重放、两种读出共享新生成表示”的比较。它仍是固定单种子、已多次查看过的五个留出集上的探索性评估。重放保持最终校准器、标准化参数及阈值冻结，并未重新选择最优配置。

## 已完成的核验

1. 五个最终 checkpoint 均实际存在，各只有 **5 个标量参数**，约 2.7 KB。
2. 从原缓存和 checkpoint 独立重算全部逐样本分数，与保存预测的最大绝对误差不超过 **1.91e-6**；AUROC、Gap、PairAcc、FRR、RR 重算一致。A3 阈值有约 2.21e-7 的浮点差，不改变这里的指标。
3. train/val/test 缓存的 qid、partition、标签、视频与正式发布数据一致；预测无重复、缺失；训练仅含 S+/S−，各 split 的训练/验证/测试视频交集均为 0。
4. 最终脚本的梯度、checkpoint 选择和阈值选择没有直接使用 U 标签；标准化来自 Seen validation。这不能排除在多轮方法开发中使用 U 结果来选择机制或参数。
5. 原始 QD 存在性 MLP 对缓存 `hs` 计算的 logit 与缓存 `orig_logits` 误差不超过 **3.82e-6**，但这些缓存不能完全复现原基线的公开逐样本预测。
6. 使用五个原始 QD checkpoint、原始特征目录及官方 `eval_bsz=16`，重新推理 **24,818 条 setting-row 测试记录**。按原脚本 sigmoid 后保留四位小数，**每条基线概率均复现发布预测，最大误差为 0**。五划分复用部分视频，24,818 不是独立样本数。
7. 在这批相同的新生成解码状态上，同时评估原存在性头与冻结的最终标量校准器，并执行 **2,000 次配对视频聚类 bootstrap**。全局 1,217 个测试视频统一抽样，跨 split 共享相同重抽样次数，保留重复视频造成的相关性。

审计指标：[audit_metrics.json](audit_metrics.json)。全量源推理复验：[fresh_test_replay_metrics.json](fresh_test_replay_metrics.json)。逐样本输出：本目录 `{split}_fresh_test_predictions.jsonl`。

## 对用户基线表的原有数字如何解释

原表和 `results_final` 的宏平均算术都成立：

| 指标 | 发布 QD 基线 | 原最终缓存结果 | 变化 |
| --- | ---: | ---: | ---: |
| Seen AUROC | 0.747602 | 0.718107 | −0.029494 |
| Unseen AUROC | 0.514428 | 0.518724 | +0.004296 |
| Gap | 0.233174 | 0.199383 | 缩小 0.033790 |

恒等式：`Gap缩小 = Seen下降 + Unseen提高`。这里 **87.29%** 的 Gap 缩小来自 Seen 性能下降，只有 **12.71%** 来自 Unseen 增益。因此“Gap 缩小 14.5%”可以作为这个口径下的描述，却不能直接解释为拒绝识别得到同等程度改善。常数分数也能得到 Seen=Unseen=0.5、Gap=0，说明单独优化 Gap 不足以表达目标。

此表还混用了发布基线的四位小数概率和新方法的原始 logit，不能作为严格的排序性能对比。

## 会影响结论的具体问题

### 1. 分数精度改变排序，必须修正评估协议

[training/qd_detr_gmr/evaluate.py](../../../training/qd_detr_gmr/evaluate.py) 第 79、108 行先做 float32 sigmoid，再把 `pred_exist_score` 保留四位小数。`scripts/analyze_semantic_existence.py` 直接对该字段算 AUROC 和 PairAcc。

最终脚本直接对 logit 算 AUROC。理论上严格单调的 sigmoid 应保留 AUROC；有限精度饱和及四位小数舍入会产生大量同分，改变排名。新重放的 A2_alt 原基线原始 logit AUROC 为 **0.4169**，同一次推理按原格式输出后是 **0.4727**。两者对应同一个模型。

正式新版本统一保存 `pred_exist_logit`，AUROC/PairAcc 基于完整精度 logit；概率用于展示和概率阈值。历史发布表保留为旧协议，另发布修订表，不能悄悄覆盖。若需要旧协议对标，双方都用同一种概率精度，作为补充结果。

### 2. 最终产物并非报告所述的 GDCA 联合训练模型

[run_final_evaluation.py](../e2e_training/run_final_evaluation.py) 第 94–116 行的模型为：

`s = w_orig*z_orig + w_disp*z_cos_disp + w_dev*z_max_dev + w_fg*z_fg + bias`。

第 133–183 行读取缓存，训练 25 epoch、lr=0.02 的 5 个标量，损失只有 BCE。它没有更新 QD 解码器，没有注意凸池化，没有同视频配对损失，也没有删除原始 coordinate-max 存在性分支；原 logit 仍是输入项。

[技术报告](../RESEARCH_REPORT_AGY_TEST.md) 第 120、125 行写的“彻底取缔逐坐标极大化”“同视频对比正则化”不对应 `results_final`。`train_gdca.py` 是另一套较大的缓存头，`train_qsw.py` 又是另一套联合微调实验，不能把三者的方法描述和产物混用。正式描述应称为“冻结 QD 的几何与前景标量融合读出”。

另：原 GMRAdapter 是 Linear→ReLU→Linear 的两层 MLP，不能解释为仅按范数决策的线性分类器；原 checkpoint 的文本输入维度为 512，报告中的 768 也需修正。

较早 QSW 部分还把 `seen.jsonl` 的验证表现与 U 测试表现组成 Gap。该 Seen 视图来自 validation，不能与用户基线表的 **test S+/S−** Gap 直接比较；最终缓存脚本在这一点上使用的是正确的 test Seen 定义。

### 3. 缓存与原推理不一致，复现必须覆盖源输入

在 cache 上复现 5 参数 checkpoint 只证明“缓存→预测→指标”这一段。原始 checkpoint 抽样重放和全量重放均能复现发布基线，但缓存中的部分原始输出不同：各组有 48–109 条记录的概率差超过 0.01；最大概率差分别约为 0.916、0.377、0.869、0.318、0.537。现有 HQ 缓存没有完整的提取脚本/输入哈希 manifest，尚未锁定差异的具体原因。

本次全量重放提供了双方共享表示的复验，其平均结论与缓存结果接近，但它不修复旧训练缓存及验证缓存的来源问题。下一轮应统一提取 train、Seen validation、test，保存 checkpoint、源特征、配置、batch size、dtype、预处理及输出的哈希；从模型推理入口复现指标，不能只从缓存读出开始。

### 4. “几何不变”没有证明“语义可泛化”

技术报告第 124 行的“必然有 1–2 个槽锚定事件”“完全一致的物理含义”没有数据或理论保证。两个几何量对正交坐标旋转不变，并不表示其正负判别关系对动作语义变化也不变；完整融合分数还含原存在头与前景头，更不能整体称为坐标不变量。

仅用 `cos_disp` 的旧缓存 Unseen AUROC，A1/A2_alt/A3/C1/C2_alt 分别为 **0.5081/0.4844/0.5672/0.5243/0.4928**；L2 离差也只有 A3 相对明确。这反驳了“跨所有划分稳定判别”的强陈述，并未排除它在特定条件下有用。

因果归因需要同一表示、相同损失与预算下只改变聚合方式，并隔离 `fg_max`、原 logit、标准化、额外训练等因素。范数分布或槽离散度与错误相关，不足以证明 max pooling 导致退化。

### 5. 阈值表现和视觉证据仍不足

全量重放沿用原冻结阈值：

| Split | U+ 误拒率 % | U− 拒绝率 % | Unseen Rej-F1 % | U+ raw R1@0.5 % | 硬拒绝后 R1@0.5 % |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 21.72 | 25.65 | 38.09 | 24.52 | 19.78 |
| A2_alt | 0.00 | 0.32 | 0.64 | 31.55 | 31.55 |
| A3 | 10.94 | 15.99 | 26.76 | 44.27 | 41.15 |
| C1 | 0.62 | 3.33 | 6.43 | 41.98 | 41.98 |
| C2_alt | 34.78 | 36.22 | 47.67 | 38.26 | 28.70 |

A2_alt 几乎接受全部 U−；A3 的已发布基线 U− 拒绝率为 31.31%，当前约 15.99%，以更低误拒换来更多错误接受。AUROC 提高不保证特定 Seen 阈值下的拒绝效果提高。这里的 R1 是硬 gate 诊断，不能替代官方 GMR 总分。

原脚本只保存存在分数，没有完整 GMR 预测集及 Rej-F1、G-mIoU 报告。GMR 论文将拒绝、正例定位、整体表现分别评价，正式结论需要同时覆盖这些指标。[GMR 原论文，第 3.3 节](https://arxiv.org/html/2605.02623v1#S3.SS3)。

本次在 A2_alt train 的 230 个完全相同文本、正负标签均出现的组中，按发布行顺序抽查前 20 组，文本 `last_hidden_state` **20/20 不相同**，例如最大逐元素差 0.0078125、0.009765625；两组向量的形状均相同。已有工作记录也记载来源混用风险。这证明特征一致性有问题，尚未证明该差异解释了本次收益。

应统一编码相同字符串并强制跨标签/分区 bitwise 一致。已有 text-only 对照在 C2_alt 的 matched-U PairAcc 为 **0.8182**，高于当前方法约 0.6364；同视频不同查询的 PairAcc 不足以证明视频理解。更有辨识力的控制是 **完全相同 query 在真实存在和确认不存在的视频上的排序**。

## 下一轮实验顺序

### P0：先修复和冻结实验口径

- 保存完整 logit，基线和方法用同一推理、预处理、精度和 test S/U 定义；历史表作为旧版本保留。
- 正负文本特征通过相同 encoder/tokenizer/checkpoint/dtype/归一化生成，相同文本共享同一缓存项。统一重建后，应重新训练原 GMR 基线与候选方法；仅给旧 checkpoint 更换特征不能隔离它之前学到的来源差异。
- 缓存有可运行提取脚本与 manifest，覆盖数据、实际源特征、模型、配置和 dtype。分开命名 QSW、GDCA 大头、最终标量融合实验。
- 预先定义成功标准：Unseen AUROC 提高、Gap 缩小，且 Seen 不出现实质退化。例如把 Seen 非劣容差事先设为 1 个百分点，并另报告固定阈值的拒绝/定位代价。容差是实验设计选择，不是本次结果推导出的统计事实。
- 训练/开发仅用 Seen；现有五组 U 已经反复查看，作为探索集。确认性结论需要事先冻结新的语义留出集。A1/A2/A3 并非互不重叠的视频域。

### P1：先检验当前 5 参数机制是否有独立价值

冻结同一 QD 与候选，先在训练侧伪留出语义上比较：

| 对照 | 要回答的问题 |
| --- | --- |
| 原完整精度 `orig_logits` | 真正的起始水平 |
| 原始 max→MLP 头按同样额外预算 refit | 增益是否只是额外训练/新头 |
| 仅 `fg_max` | 是否只是使用了另一现成分数 |
| `orig + fg` | 几何量是否带来超过简单融合的收益 |
| `orig + cos_disp`、`orig + max_dev` | 两个几何量各自是否有用 |
| 全部四信号融合 | 相对上述对照的净收益 |
| 四信号无几何项、去掉各单项 | 收益归因与交互 |
| 权重允许为 0，与当前强制正下界对照 | 是否被迫融合无效信号造成 Seen 损伤 |

训练数据、更新次数、初始化方案和开发搜索预算事先固定。纯 temperature/正 affine 校准可作数值控制：在完整精度上不能改变 AUROC，不应当作排序改善方法。禁止再次按这五组 U 的结果挑最优融合权重。

伪未见划分如果只重新训练读出、而冻结骨干已经在该语义上受过 GMR 监督，只能叫读出压力测试；要模拟完整下游语义未见，内层骨干训练也必须排除该语义。

**继续条件：**几何项在开发集上超过 `orig + fg`，并保持 Seen 非劣，才进入新留出确认。若不能超过简单融合，停止把几何机制当作主要贡献；它仍可作为诊断特征。

### P2：验证真实 query–video 对应，而非文本先验

- 完全相同 query、正视频与确认 absent 负视频的配对排序；同 query 的文本特征应严格一致。
- text-only 与 video-only，对照同一数据/预算。保留原 matched-U PairAcc，但明确其是同视频不同查询。
- 在视频时长、候选数量尽量匹配的条件下，多次视频置换，排除同视频置换、同事件误配；报告 paired 的原始与置换性能变化。不能用一次乱序后 AUC 接近 0.5 宣称所有捷径已排除。
- 若做配对损失，按 pair 组织 batch，并记录实际有效正负对数。随机打散 mini-batch 可能几乎没有有效同视频对；最终现有脚本根本没有该损失。
- 若怀疑候选局部证据不足，比较预测窗、匹配长度随机窗和 GT oracle 窗，只用于诊断。GT 不得用于实际方法选窗或测试打分。

工作记录中 P1 proposal-conditioned support 与 P2 随机 reference-centering 先前均未通过 Seen 门；不应直接重启同配方或扩大随机 bank。新的局部支持设计应先证明超过简单原分数融合，并通过同 query 的视觉对应控制。

### P3：再做严格的聚合方式归因

在同一表示和同等训练预算下比较 coordinate-max→MLP、逐槽 MLP→scalar-max、mean/attentive convex pooling、逐槽分数加前景证据。把池化方式与几何信号设计为 2×2 因素；保留标准化和 loss 一致。

先冻结表示做读出干预；再比较原 Adapter 和候选 Adapter 的同预算联合训练。保留定位损失、辅助损失配置，并记录可训练参数。这样才能区分聚合失效、表示失效、loss 和额外微调的效应。直接复用按原池化训练的头换一种池化，只能算推理干预，不能独立证明新池化更优。

### P4：确认泛化、稳定性与 GMR 代价

- 候选通过 P1/P2 后，QD 上 baseline 与候选至少 3 个配对训练种子，事先固定；成功后再扩展至 Moment/Flash，避免先铺开大量不明归因实验。Flash 的结构与 DETR 槽不同，按实际表示定义聚合。
- 新语义留出上，只执行冻结方法的确认性评估。按 action 与 composition 两轴分别报告，以及每个动作/组合的正负数和效果。
- 用 test S+/S− 与 test U+/U− 算 AUROC；按视频配对 bootstrap，跨 split 保留共享视频相关性；种子结果单独报告均值与标准差。
- 在 Seen validation 固定阈值，报告 U+ FRR、U− RR、Rej-F1、raw/gated R1、G-mIoU@1/@3。若额外报告固定 TPR 的 FPR/拒绝率，明确它是 ROC 曲线诊断还是 Seen 固定运行点，不能在 U 上选部署阈值。
- 若要声称适用于完整 GMR，补含真实多时刻样本的评估；当前 Charades 派生留出主要支持语义未见的存在性分析，不能直接推出 Soccer-GMR 多时刻场景同样改善。

## 可采用的当前结论表述

“在五个下游语义留出上的单种子探索实验中，冻结 QD 的四信号标量融合缩小了 Seen–Unseen AUROC Gap。统一源推理及完整分数精度后，平均 Unseen AUROC 提高约 1.56 个百分点，但其视频聚类区间包含零，且平均 Seen AUROC 下降约 3.28 个百分点。收益集中在 A2_alt/A3，固定 Seen 阈值的负例拒绝仍不足。因此尚不能认定该方法稳定缓解了未见语义拒绝退化，聚合和几何机制的贡献仍需受控实验验证。”
