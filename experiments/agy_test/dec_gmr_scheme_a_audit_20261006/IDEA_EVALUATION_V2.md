# DEC-GMR V2：idea-evaluator 评估与最小实验计划

评估日期：2026-10-06。

对象：`agy_test/cross_backbone_transfer_verifier/GENERALIZATION_DROP_COMPARISON_V2.md`，以及该文档引用的方案 A 代码、机器指标和此前独立复算产物。本轮没有重新训练，也没有修改原报告或原预测。执行 idea-evaluator 的早期缺陷检查、五维评估和研究可行性判断。

## 1. 第一印象与定位

**论文类型：方法研究，属于现有 GMR 问题上的增量方法。**

可成立的故事是：冻结定位骨干，用视频与查询的独立匹配证据校准存在性分数，减少未见语义下的错误接受。

目前实现是基于缓存的外部存在性分数校准：查询规则路由多模态证据，再与检测分数的分位数做乘积。`evaluate_dec_gmr.py` 没有访问 decoder states、改变 decoder 或重新计算 decoder 内部注意力，因此不宜称为“内生 Decoder 校验”。外部校准本身可以是有效贡献，但贡献名称应与实现一致。

### 是否 work：分开回答

- **当前缓存上的 Unseen 排序改善：有证据。**修正并列排名并冻结训练参考 CDF 后仍有增益。
- **完全独立单骨干推断：尚未证实。**局部证据共享上游 HQ 候选。
- **实际拒绝识别改善：尚未证实。**当前核心结果是 AUROC，缺少同协议阈值下的 Rej-F1 与定位评估。
- **Decoder 最大池化是主要根因、乘积门控专门修复该根因：尚未证实。**这是待做干预实验的假设。

|---|---:|---|---|

| Faster：速度 | 5/10 | 算子无优化训练；现有秒级计时来自缓存，未计视频解码、CLIP/SlowFast 和候选生成，无法认定整体更快 | 同硬件计端到端延迟、显存、吞吐，区分缓存与完整推断 |
| Stronger：鲁棒性 | 7/10 | 三骨干五划分方向一致；新语义未参与设计、批次独立与原生候选的鲁棒性仍缺 | 冻结方法后评估新动作/组合，做顺序、批次和查询改写诊断 |

## 6. 可行性与决定性实验

| 风险 | 程度 | 处理 |
|---|---|---|
| 计算 | 缓存评估低，重新训练骨干中等 | 优先缓存级公平对照，确定需要池化干预后再训练 |
| 数据 | 中 | 现有测试语义已反复用于分析；需要未参与设计的新留出集 |
| 工程 | 中 | 固定 CDF、QID 对齐、自身候选、A/B 输出目录隔离 |
| 时间 | 未知 | 按下述 P0→P1→P2 顺序推进；未提供投入时间，不能承诺完成日期 |

### P0：先建立可引用的主结果

1. **公平存在性分数。**读取各骨干未截断原始 logit；比较原 logit、sigmoid 概率及保留并列的排名，统计饱和和 ties。精确单调变换不改变 AUROC，浮点 sigmoid 饱和会丢失排序，应区分数值问题与语义错误。不能只对新方法修复数值而让基线保留损失的信息。
2. **冻结标准化与参数。**训练参考 CDF 保留并列；Seen 验证选路由权重、指数比和阈值。测试不重拟合，不按分区单独排名。同一输入换行顺序或换批次应得到同分数。
3. **候选来源对照。**三骨干 × 自身预测候选/共享 HQ 候选；相同视频和查询编码。这里只重提候选局部聚合，不必先重训大模型。若自身候选也提升，才支持独立骨干接入的核心主张。
4. **完整 Table 2 协议。**对每个 backbone、Baseline/+Verifier、Seen/Unseen，报告 AUROC、Rej-F1、G-mIoU，并补充 RR、S+ FRR、U+ FRR、PairAcc。阈值仅在 Seen 验证集选定后固定。沿用原 GMR 的精确定义，记录空集合和多窗口处理，不能以普通 mIoU 替代 G-mIoU。
5. **统计。**同视频聚类配对 Bootstrap 联合计算 ΔUnseen、ΔSeen、ΔGap；跨划分共享视频时联合处理其依赖。主张保持 Seen 时，应事先指定应用可接受损失做非劣性分析，而非看完测试结果再设门槛。修正后的分数需新的置信区间。

### P1：证明方法结构带来新增价值

固定候选、特征、训练 CDF 和选参预算，在 3 骨干 × 5 划分比较：

| 变体 | 回答的问题 |
|---|---|
| Detector only：原 logit / 排名 | 归一化本身是否改善？保留并列时单流单调变换应保持排序 |
| Evidence only | 是否直接抛弃检测器就能取得相同收益？ |
| 加权和、min、无权乘积 | 幂律乘积是否超过简单融合？ |
| 幂律乘积 | 当前核心结构是否有额外价值？ |
| 统一证据、无关键词路由、词元路由 | 增益是否来自按已知语义制定规则？ |
| CLIP only / SlowFast only / 去方向 / 方向取绝对值 | 动力学、方向性是否必要？ |
| 视频置换、查询错配、候选错位 | 模型是否依赖真实对应，而非词频或背景？ |

AUROC 只依赖指数比例：对正数分数，`r_det^a*r_ev^b` 的排序等价于 `r_det*r_ev^(b/a)`。因此扫描 `b/a`，不必把两个指数当成完全独立参数。用于阈值或校准时需另行固定最终分数尺度。

如果简单融合或证据单独在同协议下稳定匹配/超过幂律乘积，就应放弃“幂律连结是核心突破”的叙述，把研究转为经验证的视觉证据校准；不要继续以现有结构名称掩盖结果。

### P2：证明泛化和根因

1. **新的留出语义。**现有五划分作为开发分析集；冻结路由、指数与阈值后评估新动作/新组合。额外检查同义改写、未命中词表查询、不同视频长度。
2. **Decoder 池化干预。**在 Moment/QD 上比较 channel-wise max、mean、先逐 slot 预测再聚合、query-conditioned pooling；需要使用各自 Seen 训练/验证协议公平训练头部。各池化版本都测 ±Verifier，判断增益是否主要针对 max。
3. **诊断链条。**按正/负与 Seen/Unseen 统计 raw logits、饱和比例、不同通道 argmax slot 一致性、误接受关系。跨 slot 拼接可能发生不等于它导致假阳性；只有关联加干预才能加强根因论证。
4. **时序检验。**若主张方向证据，加入反转/打乱视频帧、相反动作查询，并检查方向分数与性能按预期变化；这仍不自动证明完整因果关系。
5. **真实开销。**报告原始视频到输出的完整延迟、显存及额外预训练模型依赖。

### 文档必须同步修正的事实

- `A2_alt` 实际为 drink/pour，不是 open/close；`A3` 为 run/walk，不是单独的 slow/fast；`C1` 为 sit 与 bed/chair/couch 的留出组合；`C2_alt` 为 open/close 与 box/cabinet。依据 `data/release/semantic_existence_v2/selection/split_specs.json`。
- 当前两路因子均取小于 1 的指数。对 `0<r<1`，`r^0.85>r`，不能解释为“高次幂强力压低低证据”。乘积可以降低联合分数，但不构成二值一票否决；只有因子为 0 时强制输出 0，且 rank 的 0 只是参考分布最小值，不等于物理证据缺失。
- Moment/QD 存在性头确实可做 decoder slot 的按通道 max；Flash 的代码是视频时序特征池化与查询拼接。不能把三个骨干都归因于同一种 decoder-query 池化。
- Moment 的 Unseen 0.6136 低于文中旧 SDCV 0.6164，不能称该项“反超”。旧 SDCV 数字本身也需按此前审计结果重新确认，不能直接做科学结论。
- 表内置信区间是 ΔUnseen 的区间，不是 Gap 缩小或完整单骨干链路的证明。AUROC 差值使用 pp，避免和相对百分比混淆。

## 7. 总体裁决

**Accept with Revisions：方向值得继续，修正协议并补齐结构证据后再形成论文主结论。**

已有证据支持“固定视频证据有助于缓解 Unseen 排序退化”，尚未支持“内生 Decoder 因果连结、纯单骨干无代价拒绝、机制专属性已经证明”。

优先三件事：

1. 原始 logit + 保留并列的训练 CDF + 各骨干自身候选，重建公平主表。
2. Evidence-only、加权和、min、无权乘积、当前幂律乘积及去路由，先判断核心方法是否超过简单控制。
3. Seen 阈值下完整 GMR 指标和新语义冻结评估，联合报告收益与 Seen 损失。

独立复算数值与脚本见同目录 `SCHEME_A_INDEPENDENT_AUDIT.md`、`audit_metrics.json`、`audit_scheme_a.py`。
